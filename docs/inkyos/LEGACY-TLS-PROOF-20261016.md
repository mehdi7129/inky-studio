## Endpoint and transport

`POST /api/auth/legacy-tls-proof` accepts exactly:

```json
{"v":1,"nonce":"64 lowercase hexadecimal characters"}
```

`v` is a strict integer; booleans, floats and strings are refused. The nonce is
exactly 32 bytes encoded as lowercase hex. Extra/duplicate fields, malformed
JSON and noncanonical values return a generic 422. A streamed body is limited
to 2048 bytes (413 on excess). The process-global throttle uses one fixed key
and at most 30 timestamps over 60 monotonic seconds; changing source/forwarded
addresses cannot enlarge it. Excess attempts return 429.

This single endpoint is public on HTTP as well as HTTPS. Its exact-path
middleware branch bypasses application cookie/session authority and attaches
`Cache-Control: no-store`, including method and validation failures. Cookies
supplied by an unrelated browser session are ignored; no cookie is issued.
FastAPI may parse cookies internally; no authentication/session call consumes
them for this endpoint. The existing CORS layer also applies no-store to early
preflight responses on this exact path, without changing its origin policy.
Only POST can return a proof. It performs no redirect or outbound request.
The client sends only its fresh nonce, never the QR password, cookie or device
token over this unauthenticated transport.

The response has exactly `v`, `nonce`, `identity`, `proof`. Identity contains
`frame_id`, `spki_sha256`, `url`, obtained with existing
`public_identity(request, with_url=True)`: only the already-loaded public
certificate is used, and `INKY_STUDIO_PHOTO_ACCESS_URL` must be explicit.
No Host/forwarded host/address discovery is used to construct that origin.
No identity/key file is opened or generated by this endpoint.

All existing device/enrollment/invitation endpoints retain their HTTPS-only
transport checks. Both production listeners retain `proxy_headers=False`.
The HTTP exception is not a way to send PHOTO credentials or establish a
session; the response alone grants no access.

## Credential binding and MAC

The operation holds `auth_service._lock` from reading the current credentials
through durable record comparison, public identity extraction and HMAC. It
uses only the existing loaded `bootstrap_password` when it has exactly 16 ASCII
alphanumeric characters. The durable record is read without creating,
migrating, repairing or chmodding it; keys, value types and values must exactly
match the current RAM record. A missing/custom/invalid bootstrap, missing or
changed durable record, unavailable public identity or missing/invalid origin
returns the same fixed 503: `Preuve HTTPS indisponible`. Auth disabled returns
409. No bootstrap or other secret appears in a response or log.

The HMAC-SHA256 key is the UTF-8 bootstrap secret. The message is the exact
concatenation:

```text
ASCII("inky-legacy-tls-proof-v1") || NUL
|| nonce[32 raw bytes] || UUID[16 RFC bytes] || SPKI-SHA256[32 raw bytes]
|| uint16_big_endian(len(URL_UTF8)) || URL_UTF8
```

The exact returned URL bytes are authenticated; clients must not normalize the
URL before MAC verification. The nonce is reflected exactly and the proof is
lowercase hex. No nonce, grant, credential, session or ownership receipt is
persisted; only the bounded in-memory throttle changes.

## Boundaries

The iPhone must recover its previously saved QR secret through native device
owner authentication, generate a fresh unpredictable nonce, reject redirects,
validate the complete response and verify the HMAC locally. Only then may it
use the returned UUID/SPKI in its strict pinned TLS transport, send the original
QR secret over TLS and enroll a protected PHOTO credential. Stale/backgrounded
completions must not replace a different frame or lock generation.

No QR secret recovery is provided if that secret was already lost. A custom
password has no bootstrap proof. If the capability is unavailable, the client
must retain the previous connection and protected data; no TOFU or TLS policy
downgrade is permitted. The endpoint does not configure a real sharing origin.

Factory startup selection and refusal remain unchanged. This proof is neither
factory/BLE ownership nor a first factory PHOTO handoff. Time/country/Wi-Fi,
`SystemSetup` and Phase B stay outside this lot. The existing Inky 2.5.0 pin and
the physical qualification limits documented by the parent merge are unchanged.
